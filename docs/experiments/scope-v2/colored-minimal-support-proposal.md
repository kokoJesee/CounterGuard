# colored 普通元组入口的受限支持提案

状态：**维护者已批准受限实施**；精确版本、grammar、拒绝与重算规则见[实施规格](../../static-reexports-v2.md)。
本批准不包含执行 colored，不新增生产开关或跳过未知项的参数。下文保留提案时的工程范围与估算。
提出它的原因是[五项筛查](../../results/bounded-rgb-targets-v1/README.md)已用尽，仍无合格目标，但 colored 有明确的夹紧规范与较集中的工程阻塞。

## 固定对象与要回答的问题

目标仓库 `https://gitlab.com/dslackw/colored.git`，固定提交 `f3d799873a7cde62f3c43d74ed6ffc258240d956`，公开目标 `colored:cprint`，
定义 `colored.cprint:cprint`、文件 `colored/cprint.py`。不是 Click，不涉及 legacy 元数据。

现有来源为 termcolor 的已验证 RGB Guard；本提案保留全部 8 case、ValueError 和原消息 match。
目标通过 `fore_rgb/back_rgb` 接收原元组，来源 force_color 的处理必须显式声明，禁止转发到 print 的 **kwargs。
文本与数据值不改，适配器不先解包元组、不拦截或改写目标异常。
具体逐 case 数据已写入[非执行映射工作表](../../results/bounded-rgb-targets-v1/colored-cprint-proposal.json)。

预期可以研究的假设是：来源要求拒绝的越界 RGB，在目标自己的夹紧规范下允许被修正；
原 Guard 在目标上的报警可能是错误应用。上游夹紧测试提供规范见证，但具体 case、消息差异、目标内部长度错误仍需独立审核。
不提前分配适用标签，不承诺数据会满足主判据，不删除 source match 来得到有利结论。

## 提议的最小工程范围

### A：新版本的静态根导出绑定

保留现有 static-root-reexport.v1 / contract.v5 的 grammar 与拒绝行为，新增独立版本；拟议算法名为 static-root-reexport.v2，
具体契约/绑定/派生模型编号在实施前盘点冻结，不能用新模型字段偷偷复用旧版本。

拟支持：根包多个具名导入，但目标名字只允许一次、可追溯至同包直接子模块的普通顶层函数；
根包只接受有界 docstring、受限 from-import、字面量 __all__，以及未被重绑定的内置 str 注解下的字面量 __version__。
不得泛化为任意带注解赋值。需要保留根包所有实际导入和初始化源码，定义模块的相对导入也必须逐项跟踪到完整 pin。

继续拒绝：根包条件/动态导出、模块 __getattr__、星号导出、重复/覆盖目标绑定、任意顶层执行、跨包目标、命名空间缺项、
循环/多跳目标别名、未知装饰器、动态默认参数。不能复制 cprint 到一个新模块逃避原包初始化。
与完整闭包检查分开：绑定认出一个名字，不等于它的包已通过安全审核。

### B：按真实作用域区分钩子，限定可审核的类钩子

现有检查把 AST 中所有名为 __getattr__ 的函数都记为 module_lookup_hook_requires_review。
新 closure 版本首先区分模块、类、元类和嵌套函数；模块条件分支中定义的钩子仍属于模块作用域，不可漏掉。
导入别名、赋值等模块级 __getattr__ 绑定也应拒绝或明确 unknown，不能只检查顶层 FunctionDef。

对本候选的三个类/元类钩子，初步仅考虑受限的“raise 已核验异常”形式：参数、raise 目标及异常类定义可追溯，
无动态转发、任意 helper 调用、导入、资源访问或返回计算值。类钩子的真实动态效果必须独立列为审查观察并绑定源码 pin；
不是把所有类钩子直接从 finding 中删掉。若该有限规则不能无歧义表示，就停在诊断改进，不获得执行资格。

模块末尾的 Windows 终端初始化、类构造和元类代码、环境读取与 ctypes 路径仍需逐项审核；
不改变网络关闭、文件系统/用户/资源限制、精确 runner 身份或宿主禁执行策略。
不添加“review override”来抹掉剩余 unknown，也不因为计划只在 Linux 执行就删减未经证明的上游源码。

### C：版本、来源链与验证

新契约明确选择新绑定/closure 版本；旧版本继续旧路由，不能自动放宽接受范围。
契约、binding、capture、Guard、Registry 的读写和独立重建路径须逐一盘点受影响 union 与 schema；
对新增版本显式支持，对未知版本拒绝，禁止降级成旧模型后忽略字段。

目标静态审核与来源捕获分别处理：比较目标不要求自己的 B/F/H；来源 termcolor 的 B/F/H 要求完全保留。
本阶段只让有据可查的目标材料达到可行性准入，并通过工具自有 Docker fixture 证明新 grammar 和隔离边界。
**colored 的真实跨项目运行仍要等独立研究目标/调用映射/授权桥接完成；不能使用生产 snapshot Scope 换仓库来提前执行。**

必要验证：

- 肯定样例：静态多导出、唯一普通函数、版本字面量、限定的类钩子；逐角色源码/定义/初始化器绑定。
- 否定样例：所有上述越界 grammar，真假模块/类钩子、条件绑定/别名重绑、危险异常构造、动态转发、初始化副作用和未知字段。
- 完整性：漏/换 closure 文件、修改目标导出/类钩子/版本字面量/runner/policy 均拒绝；旧模型不能吞新字段。
- 回归：旧版本接受/拒绝不变，原 termcolor 8 case 与 oracle 不变，数据无标签泄漏，20 次乱序结果与语义摘要一致。
- 执行：新增实际 Git/Docker 测试标 slow；仅工具自有 fixture 在本阶段执行。准入失败时 run=null、无宿主回退。

日常 `uv run pytest -m "not slow" -q` + 相关专项 + Ruff，不跑全量；不把 Docker 专项的通过当外部目标或研究样本。
开始编写接受逻辑前，先冻结精确 grammar、版本路由、拒绝码、依赖重算清单与安全 fixture。

## 成本与停止条件

| 工作包 | 工程初估 |
|---|---:|
| 静态根导出新版本及绑定盘点 | 1–2 人日 |
| 作用域辨识与有限类钩子审查 | 0.5–1 人日 |
| 独立重建/隔离专项、旧版本回归及文档 | 1–2 人日 |
| 固定包完整源码复核、准入回执与交接 | 0.5–1 人日 |

合计 **3–6 人日初估**，不是日历承诺或实测时长。新模型传播、元类/初始化行为审核可能增加工作量，结论不确定。
不包括独立研究执行桥接、研究特征支持、更多数据采集、维护者等待或完整科学评测。
新能力成功也不等于有足够独立项目/留出 true_bug 可以证明泛化。

出现以下任一项就停止，不在本提案中继续扩张：需要 legacy/依赖安装/conftest 加载；任意动态根导出或任意类钩子；
需要把目标代码改写为包装器、丢掉源 case、修改 oracle、伪造标签或绕过精确快照；有限类钩子规则无法可靠表示。
谱系审核、目标规范与来源全部输入映射任一项不成立，照实保留未接纳，不为已有投入调整标准。

## 重新物化与不变量

提案提交本身未改变产品摘要；获批实施将改变源码的全包 implementation_digests，旧执行/绑定会按规则判 stale；
使用新 ID/目录重新生成需要的 plan/binding、授权、Evidence、Guard、Registry，旧文件不可覆盖。
termcolor 原 contract.v5 内容/投影不变且旧路由仍受支持时，可重新核对并复用已有所有者 H，无需伪造新提交。

后续研究桥接另用新目标/映射/特征/协议与下游产物版本，不修改 scope_v1 标准、标签、实验、split/context、examples 原实现/契约或既有 artifact。
不移动发布标签；不新增运行时依赖；不默认打开 Shadow/Active。

## 实施批准的边界

实施 A–C 的受限范围，不扩搜第六项；不做旧式元数据、pytest 参数展开、类方法 target、命名空间包或 Click 支持；
不运行 colored、不创建 fork/H、不生成新来源契约、不确定标签；不把该提案当成跨项目研究已完成。
维护者也可以选择不扩大 profile，保留 insufficient_data 并缩窄可交付主张，两种选择都不得改写历史事实。
